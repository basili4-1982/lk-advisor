# LK Advisor — ИИ-агент рекомендаций в личном кабинете

По профилю клиента сервис отдаёт top-3 уместных предложения с объяснением
и соблюдением бизнес-правил, а по вопросу — обоснованный ответ с инструментами.

Хакатон «ИИкузница 2026», трек «Клиентские сценарии».
Спринт: **26.11.2026 10:00 — 28.11.2026 10:00 МСК**.

**Статус:** рабочий бэкенд. `POST /v1/recommendations`, `POST /v1/ask`, тесты и eval на 50 кейсах.

## Что делает

- `POST /v1/recommendations` — клиент на входе, top-3 с причиной и evidence на выходе.
- `POST /v1/ask` — вопрос по клиенту: агент вызывает инструменты, помнит сессию и отвечает по отчёту из БД.
- Числа считает код; LLM только формулирует и не может добавить число, которого нет в evidence.
- Правила (несовместимость, экспортный контроль, уже куплено, менеджер, склад, окружение)
  применяются до скоринга и до LLM.
- Акция повышает срочность, решает равенство score и показывается в ответе.
- Нет кандидатов — fallback на популярное в сегменте.

Не делаем: интерфейс, реальные интеграции, оплату, рассылку, мультитенантность, обучение моделей.

## Быстрый старт

```bash
make db-up       # PostgreSQL 16 на :55432
make migrate
make seed        # seed 42
make run         # сервис на :8080
```

Откройте `http://localhost:8080/` — это демо-кабинет: профиль клиента, покупки, лицензии, рекомендации и ассистент. Описание API — `http://localhost:8080/api`.

```bash
curl -s localhost:8080/healthz
curl -s -X POST localhost:8080/v1/recommendations \
  -H 'Content-Type: application/json' -d '{"client_id":"smb-002"}'
curl -s -X POST localhost:8080/v1/ask \
  -H 'Content-Type: application/json' -d '{"client_id":"smb-002","question":"Почему векторный?"}'
```

Настройки — в `.env.example`. Ключ LLM берётся из `LLM_API_KEY`, если пусто — из `DEEPSEEK_API_KEY`.
Без ключа агент отвечает шаблоном.

## API

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/healthz` | проверка живости |
| POST | `/v1/recommendations` | top-3 рекомендации по клиенту |
| POST | `/v1/ask` | вопрос по рекомендациям, инструменты и evidence |

## Архитектура

- Профиль — материализованное представление PostgreSQL по 8 шардам, обновление по триггеру.
- Каталог, связи и акции — PostgreSQL; графовая БД понадобится только при многошаговых обходах.
- Движок: интенты → кандидаты → правила → скоринг → разнообразие → top-3.
- Агент: извлечение продуктов и типа вопроса → отчёт из БД → инструменты → ответ → guard.
- Guard: числа по evidence, нет PII, нет утечки промпта, лимит длины.
- Админка `/admin`: связи, шаблоны типов связей, правила и веса без пересборки; ИИ-помощник показывает diff и применяет только после подтверждения.
- Типы связей редактируются как шаблоны: описание и примеры идут в промпт разметки, поведение говорит движку, как использовать связь.
- Агент разметки: пара товаров → тип из шаблонов, уверенность, evidence; запись только после подтверждения.
- Ручная валидация: очередь `quarantine` / `llm_suggested`, подтверждение и отклонение, заметки и аудит.
- Агентная аналитика: стратегия и сегмент в событиях, авто-А/Б, веса B2B/B2C, health-очередь для слабых связей.
- Обратная связь: boost/penalty по товарам, exploration-слот, учёт позиции клика.

## Тесты и eval

```bash
make db-up
make test        # go test -p 1 ./... (пакеты делят одну БД)
make eval        # 50 кейсов, пороги precision/recall
```

Текущий eval: `precision@1 = 0.90`, `precision@3 = 1.00`, `recall@3 = 1.00`,
нарушений 0, fallback 0, evidence 100%. CI гоняет тесты и eval на PostgreSQL.

## Экономика

Один запрос рекомендации — один вызов LLM: 2 000 вх. + 300 вых. токенов, **0,048 ₽**
по ценам RouterAI. 10 000 запросов — **≈477 ₽/мес**. Подробно: `economics.md`.

Для демо используется прямой DeepSeek API; его цена может отличаться от RouterAI,
перед сдачей расчёт пересчитывается.
