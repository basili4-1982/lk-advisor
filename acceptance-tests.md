# Приёмка

## 1. Шесть сценариев

| # | Запрос | Ожидание |
|---|---|---|
| 1 | `client_id=smb-001` — без события | `intent=renewal` по сроку лицензии, первая — продление или пакет на продление, в evidence есть дата окончания |
| 2 | `client_id=smb-002` — без события | `intent=cross_sell`, первая — соседний продукт или пакет к купленному |
| 3 | `client_id=smb-003` — без события | `intent=upsell`, первая — старший тариф по `upgrade`-связи, в причине — связь с купленным продуктом |
| 4 | `client_id=smb-004` с несовместимым товаром | запрещённого `product_id` нет в ответе |
| 5 | `client_id=smb-005` с апгрейдом только через менеджера | товар есть, `constraints` содержит `manager_approval` |
| 6 | `client_id=smb-006`, истории нет | `fallback=true`, популярное в сегменте или пустой список |

Событие визита не требуется: сценарии 1–3 идут без него. Отдельно проверяем, что `smb-001` с `event=license_view` не ломает ответ — событие уточняет порядок, но ядро остаётся профиль.

## 2. Правила

| Проверка | Ожидание |
|---|---|
| несовместимая лицензия | исключена |
| экспортный контроль | исключён |
| товар уже куплен | исключён, кроме апгрейда |
| апгрейд только через менеджера | оставлен, помечен |
| нет в наличии | исключён или помечен |
| активная акция | повышает `urgency` и решает равенство score |
| просроченная акция | не влияет на порядок |
| скидка выше `max_discount` | обрезается до лимита |
| акция на запрещённый товар | не поднимает его |
| после фильтров пусто | fallback, без запрещённого |

## 4. Качество

50 кейсов из `ground_truth.csv`.

| Метрика | Порог |
|---|---:|
| precision@1 | ≥ 0.70 |
| precision@3 | ≥ 0.90 |
| recall@3 | ≥ 0.80 |
| нарушений правил | 0 |
| fallback rate | < 10% |
| доля ответов с evidence | 100% |

## 5. Детерминизм и честность

- Один и тот же запрос при seed 42 даёт одинаковый JSON.
- В `reason` нет чисел, которых нет в `evidence`.
- В ответе нет PII: только `client_id`, товары, причины.
- `score` не меняется между запусками.
- Fallback не содержит запрещённых товаров.
