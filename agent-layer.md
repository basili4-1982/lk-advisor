# Агентский слой: `/v1/ask`

Цель — закрыть критерий 5 «Агентность»: инструменты, многошаговость, память.
Числа возвращают только инструменты; LLM формулирует ответ и не считает.

## 1. Контракт

```http
POST /v1/ask
```

```json
{
  "client_id": "smb-001",
  "session_id": "ses-7f3a",
  "question": "Почему векторный редактор?"
}
```

```json
{
  "session_id": "ses-7f3a",
  "intent": "why",
  "answer": "Векторный дополняет растровый: это соседняя задача, а не замена.",
  "tool_calls": [
    {"tool": "get_recommendation", "args": {"client_id": "smb-001"}},
    {"tool": "get_evidence", "args": {"product_id": "prod-vector"}}
  ],
  "evidence": [
    {"source": "relation", "value": "raster -> vector, adjacent_task, 0.82"},
    {"source": "purchase", "value": "prod-raster, 2026-10-12"}
  ],
  "fallback": false
}
```

`tool_calls` отдаём наружу специально: на демо видно, что агент вызывает инструменты, а не «магически отвечает».

## 2. Инструменты

| Инструмент | Что возвращает |
|---|---|
| `get_recommendation(client_id)` | top-3 из основного пайплайна |
| `get_profile(client_id)` | профиль из MV: лицензии, покупки, окружение |
| `get_relations(product_ids)` | рёбра: тип, направление, уверенность, статус |
| `apply_rules(candidates, client_id)` | что отсечено и каким правилом |
| `score_candidates(candidates, client_id)` | score и rank по пяти признакам |
| `get_evidence(product_id, client_id)` | evidence для причины |

Все инструменты — обычные Go-функции над PostgreSQL. LLM их не заменяет.

## 3. Роутер

Детерминированный, без LLM:

| Интент | Вопрос | Цепочка |
|---|---|---|
| `why` | «почему это предложение?» | `get_recommendation` → `get_evidence` |
| `alternatives` | «почему не X?» | `get_relations` → `apply_rules` → `score_candidates` |
| `what_if` | «что если не продлить?» | `get_profile` → `get_evidence` |
| `unknown` | остальное | уточняющий вопрос, без LLM |

LLM получает результат инструментов и формулирует ответ. Нет ключа — шаблон.

## 4. Память

Таблица `agent_sessions` в PostgreSQL:

```text
session_id   PK
client_id
last_intent
last_product_ids  jsonb
updated_at
```

TTL — 30 минут. Уточнение «а что дешевле?» использует `last_product_ids` из сессии.
Без памяти каждый вопрос начинался бы с нуля.

## 5. Защита от выдуманных чисел

- Любое число в `answer` проверяется по `evidence`.
- Не нашлось — ответ переписывается шаблоном.
- Тот же инвариант, что и у `reason` в основном контракте.

## 6. Демо-сценарии

1. «Почему векторный?» → `why`, 2 инструмента, evidence.
2. «Почему не второй растровый?» → `alternatives`, правило «замена не допродажа».
3. «Что если не продлить?» → `what_if`, срок лицензии и последствия.
4. Уточнение «а что дешевле?» → память сессии, без повторного профиля.
