# Контракт ручки рекомендаций

## 1. Эндпоинт

```http
POST /v1/recommendations
Authorization: Bearer <token>
Content-Type: application/json
```

Одна ручка. Без UI. Рекомендация считается на запросе, объяснение — часть ответа.

## 2. Запрос

```json
{
  "client_id": "smb-001",
  "limit": 3,
  "locale": "ru-RU"
}
```

Событие опционально. Если кабинет его пришлёт, оно уточняет порядок рекомендаций:

```json
{
  "client_id": "smb-001",
  "event": "license_view",
  "context": {"license_id": "lic-456"}
}
```

| Поле | Тип | Обяз. | Смысл |
|---|---|---|---|
| `client_id` | string | да | клиент, для которого считаем |
| `event` | enum | нет | `login`, `order_view`, `license_view`, `document_download`, `catalog_view` |
| `context` | object | нет | `order_id`, `license_id`, `product_id` — что именно открыто |
| `limit` | int | нет | 1–5, по умолчанию 3 |
| `locale` | string | нет | язык объяснения, по умолчанию `ru-RU` |

Если `event` нет — интент выводится из истории: ближайшая лицензия к продлению, последний заказ, последняя покупка. Событие визита не требуется: это дополнительный сигнал, а не вход.

## 3. Ответ

```json
{
  "trace_id": "tr-7f3a",
  "client_id": "smb-001",
  "intent": "renewal",
  "recommendations": [
    {
      "product_id": "prod-101",
      "sku": "SL-LIC-101",
      "title": "Продление лицензии на 12 месяцев",
      "type": "renewal",
      "score": 0.91,
      "rank": 1,
      "reason": "Лицензия истекает через 14 дней, продление сохраняет текущие условия.",
      "evidence": [
        {"source": "license", "value": "lic-456, end 2026-12-03"},
        {"source": "purchase", "value": "prod-789, 2025-12-03"}
      ],
      "constraints": [],
      "price": {"amount": 42000, "currency": "RUB"},
      "expires_at": "2026-12-03"
    }
  ],
  "fallback": false,
  "generated_at": "2026-11-19T15:00:00Z"
}
```

| Поле | Смысл |
|---|---|
| `intent` | `renewal`, `upsell`, `cross_sell`, `reorder`, `analog`, `none` |
| `type` | тип рекомендации |
| `score` | 0–1, детерминированный |
| `reason` | объяснение для клиента, без выдуманных чисел |
| `evidence` | на чём основано: лицензия, покупка, заказ, правило |
| `constraints` | например, `manager_approval` |
| `promo` | скидка и срок акции, если активна |
| `expires_at` | до какой даты предложение актуально |

## 4. Ошибки

| Код | Когда |
|---|---|
| 400 | нет `client_id`, `limit` вне 1–5, неизвестный `event` |
| 404 | клиент не найден |
| 409 | нет данных для расчёта — возвращаем `fallback: true` |
| 422 | запрос противоречит правилам (например, запрошен запрещённый товар) |
| 500 | внутренняя ошибка, без утечки данных |

## 5. Batch

```http
POST /v1/recommendations/batch
```

```json
{
  "client_ids": ["smb-001", "smb-002", "smb-003"],
  "event": "login",
  "limit": 1
}
```

Ответ — массив тех же объектов. Лимит — 100 клиентов за запрос.

## 6. Правила поведения

- Один и тот же вход при фиксированном seed даёт один и тот же выход.
- Числа в `reason` берутся из `evidence`; LLM не может добавить новое число.
- Запрещённые товары не попадают в ответ даже при высоком score.
- Если после фильтров пусто — `fallback: true` и популярные товары сегмента, либо пустой список.
- `manager_approval` не скрывает товар, а помечает его.
- Акция не отменяет запреты и не поднимает запрещённый товар; `max_discount` ограничивает скидку.
- Товар, который уже есть у клиента, не предлагается, кроме апгрейда.
- Ответ не содержит PII: только `client_id`, товары и причины.

## 7. Производительность

- p95 без LLM — до 100 мс на 50 клиентах.
- p95 с объяснением — до 1.5 с.
- Batch на 100 клиентов — до 2 с без LLM.
- Кэш на `client_id + event + limit` — 5 минут.

## 8. Примеры сценариев

**Продление.** `event=license_view`, лицензия истекает через 14 дней → `renewal`, продление или апгрейд.

**Заказ.** `event=order_view`, заказ доставлен → `cross_sell`, аксессуар или гарантия.

**Апгрейд.** Клиент упирается в лимит мест → `upsell`, старший тариф.

**Запрет.** Совместимость не подтверждена → товар исключён, в ответе его нет.

**Нет данных.** Новый клиент без истории → `fallback: true`, популярное в сегменте.
