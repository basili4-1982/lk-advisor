# Настройка правил рекомендаций

Админка: `http://localhost:8080/admin`. Открывается без сборки и авторизации — это демо-стенд для жюри.

## Что можно менять

| Раздел | Что настраивается | Куда попадает |
|---|---|---|
| **Типы связей** | код, название, описание, примеры, поведение, направление | `relation_types` → промпт разметки и движок |
| **Связи товаров** | откуда → куда, тип, уверенность, статус | `product_relations` → пул кандидатов |
| **Правила** | несовместимость, нет в наличии, согласование, лимит скидки, экспортный контроль | `rules` → `recommend.ApplyRules` |
| **Веса** | релевантность, срочность, аффинность, маржа, уверенность | `settings.scoring_weights` → `recommend.ScoreWith` |
| **ИИ-помощник** | фраза на русском → набор операций → diff → подтверждение | те же таблицы |

Связи бывают встроенные и пользовательские. Встроенные:

- `upgrade` — старшая версия;
- `adjacent_task` — дополняет;
- `substitute` — замена/конкурент (показывается только как бюджетная альтернатива);
- `bundle`, `accessory`, `workflow_next_step`, `analog`, `compatibility`, `same_task`;
- `excludes` — несовместимость.

Статусы: `confirmed` — включена, `llm_suggested` — предложена ИИ, `quarantine` — на проверке, `rejected` — отключена. Движок видит только `confirmed` и `llm_suggested`.

## Типы связей

Это шаблоны, по которым LLM размечает много пар. У шаблона есть:

- **код** — латиницей, попадает в `product_relations.type`;
- **название** — как тип называется в админке;
- **описание** — что и как связывать; идёт в промпт;
- **примеры и контрпримеры** — тоже идут в промпт;
- **поведение** — что делает движок:
  - `cross_sell` — допродажа;
  - `upsell` — апгрейд;
  - `bundle` — комплект: апгрейд и допродажа;
  - `substitute` — замена, не допродажа;
  - `analog` — аналог снятого;
  - `info` — только хранить, не показывать;
- **направление** — `forward` (от купленного к предлагаемому) или `symmetric`;
- **уверенность по умолчанию** — с ней связь попадает в карантин/выдачу;
- **статус** — `active`, `draft` или `disabled`. В промпт и движок попадают только `active`.

Пользовательский тип можно удалить; встроенный — только отключить или переписать описание. Код, поведение и направление встроенного типа зафиксированы.

Пример своего типа:

```json
{
  "code": "industry_addon",
  "title": "Отраслевое дополнение",
  "description": "Отраслевой модуль к платформе: закрывает отраслевую задачу и не заменяет платформу.",
  "examples": "1С → отраслевой модуль; CAD → библиотека ГОСТ.",
  "behavior": "cross_sell",
  "direction": "forward",
  "default_confidence": 0.85,
  "status": "active"
}
```

После этого тип появляется в форме связей. ИИ-помощник тоже понимает его название: «Сделай Кибер Бэкап отраслевым дополнением к Kaiten».

## Агент разметки

В блоке «Агент разметки» выберите два товара. Агент предложит тип из активных шаблонов, уверенность, причину и evidence. Ничего не сохраняется без кнопки подтверждения. Подробно: `docs/relation-agent.md`.

## Аналитика и авто-А/Б

Вкладка «Аналитика» показывает:

- показы, пропуски, CTR, покупки и конверсию;
- таблицу стратегий по B2B/B2C;
- переключатель **«Авто-перераспределение трафика»**;
- кандидатов на проверку: товары с 50+ показами и 0 кликов.

Кнопка «Пометить связи» ставит `review_note` входящим связям. Статус связи не меняется автоматически: решение остаётся за человеком.

## Веса по сегментам

Вкладка «Веса» теперь умеет хранить разные профили:

- `default`;
- `b2b`;
- `b2c`.

Движок выбирает профиль по `audience` клиента. Изменение пишется в аудит, а событие хранит `weights_version`.

## Валидация

Вкладка «Валидация» показывает связи в `quarantine` и `llm_suggested`. Их можно подтвердить, отклонить по одной или пачкой, оставить заметку. Подробно: `docs/relation-validation.md`.

## ИИ-помощник

Примеры фраз:

- «Сделай Кибер Бэкап дополнением к Kaiten»;
- «Убери GStarCAD из рекомендаций»;
- «Ограничь скидку 5%»;
- «Согласование менеджера для Microsoft 365 бизнес премиум»;
- «Релевантность 40, срочность 20, аффинность 20, маржа 10, уверенность 10».

Помощник возвращает не готовое изменение, а **предложение**: объяснение, список операций и человекочитаемый diff. Применение — отдельным действием. Если LLM недоступна, работает разбор по правилам для тех же типовых фраз.

Защита от случайных изменений:

- ID товаров проверяются по каталогу;
- типы связей и правил — по белому списку;
- удаление правила или связи не принимается, если в тексте нет явного «удали»/«убери»;
- все применения пишутся в `admin_audit`.

## API

```bash
GET    /v1/admin/state
POST   /v1/admin/relations
DELETE /v1/admin/relations
POST   /v1/admin/rules
DELETE /v1/admin/rules/{id}
PUT    /v1/admin/weights
POST   /v1/admin/agent/propose
POST   /v1/admin/agent/apply
POST   /v1/admin/relations/agent/propose
GET    /v1/admin/relations/review
POST   /v1/admin/relations/review
POST   /v1/admin/relation-types
DELETE /v1/admin/relation-types/{code}
```

Пример предложения:

```bash
curl -s -X POST localhost:8080/v1/admin/agent/propose \
  -H 'Content-Type: application/json' \
  -d '{"text":"Сделай Кибер Бэкап дополнением к Kaiten"}'
```

Пример применения:

```bash
curl -s -X POST localhost:8080/v1/admin/agent/apply \
  -H 'Content-Type: application/json' \
  -d '{"operations":[{"action":"add_relation","from_id":"prod-sl-86","to_id":"prod-backup","type":"adjacent_task","confidence":0.9,"status":"confirmed"}]}'
```

## Проверка эффекта

В правой колонке админки выберите клиента и нажмите «Показать топ-3». Это тот же `POST /v1/recommendations`, что и в кабинете, поэтому видно реальный результат правил, а не предпросмотр на клиенте.

## Ограничения демо

- Нет авторизации и ролей — стенд локальный.
- `seed` пересоздаёт связи и правила, но не сбрасывает веса и журнал изменений.
- Изменения связей и правил живут до следующего `seed`.
