# Код-ревью: итог после исправлений

## Проверки

- `go build ./...` — ок.
- `go vet ./...` — ок.
- targeted-тесты catalog/httpapi — ок.
- OpenAPI YAML — валиден.
- Ручной прогон витрины: `C05445`, `C11191`, `COLD-RETAIL`.
- `recompute` — 19 011 клиентов, 190 110 строк, ~7 с.

## Исправлено по ревью

1. **Forced-target.** `placeForced` удаляет цель перед вставкой; падение
   `forceCandidate` больше не теряет товар.
2. **Пересчёт и читатели.** Вместо `TRUNCATE` — staging-таблица и
   `DELETE + INSERT ... ON CONFLICT`; читатели видят старые данные до commit.
   Добавлен advisory lock, чтобы CLI и сервер не пересекались.
3. **Ошибки сертификатов.** `annotateCertificates` возвращает ошибку;
   `certified_only` больше не отдаёт пустой блок при сбое БД.
4. **Experiment exposure.** Legacy-эксперимент с целью не из каталога больше не
   выбирается; treatment без показа target не пишет exposure.
5. **Лимит.** Handler принимает 1–36, как в OpenAPI.
6. **Модель.** Убран лишний neighbour-хвост >200, B2C использует популярность
   по всем клиентам, score в предрасчёте `1/rank`, добавлены детерминированные
   tie-break по `item_id`.
7. **Планировщик.** Контекст с таймаутом 10 минут и остановка по shutdown.
8. **Схема.** Индекс по `item_id` и уникальный `(client_id, rank)`; OpenAPI
   дополнен `factors`, `promo`, `exploration`, 409/500.

## Осталось

1. **Тесты и демо делят БД.** Полный `go test` может очистить связи. Нужен
   отдельный `TEST_DATABASE_URL`.
2. **XLSX и `lk_orders` расходятся:** 31 753 против 30 514 продаж. Нужно свести
   источник перед продакшеном.
3. **Короткий блок.** Если предрасчёт отфильтровался, fallback не добивает до
   `limit`.
4. **`admin.go` — монолит.**
5. **OpenAPI без контрактного теста.**
6. Нет auth и адаптера к ЛК — сознательно для демо.

## Вердикт

**К демо — готово.** Критические дефекты закрыты. Для продакшена нужны
изоляция тестовой БД, сверка источников, контрактные тесты и разбиение
`admin.go`.
