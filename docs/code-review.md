## Исправлено во время ревью

1. **Дубликат forced-target.** Если target уже был в предрасчитанном top-N,
   `applyForced` вставлял его второй раз. Вынесено в `placeForced`, товар
   удаляется перед вставкой. Тест `TestPlaceForcedDoesNotDuplicate`.
2. **Конкурентный пересчёт.** Два пересчёта в одном процессе могли пересечься
   на `TRUNCATE`/COPY. Добавлен `precomputeMu`.
3. **Холодный старт в регулируемой отрасли.** `COLD-CLINIC` попадал под
   `certified_only` и показывал один товар. Для демо холодного старта выбран
   `COLD-RETAIL`.

## Открытые вопросы

### Important

1. **Тесты и демо делят одну БД.**
   `store.TestDSN()` по умолчанию смотрит в демо-базу. Полный прогон
   `go test ./internal/catalog` может очистить `relations` и алиасы. Во время
   ревью это произошло; связи восстановлены через reset + повторную генерацию.
   Нужен отдельный `TEST_DATABASE_URL` или транзакционная изоляция.

2. **Расхождение данных XLSX и `lk_orders`.**
   В v5 XLSX 31 753 продажи, в `lk_orders` 30 514. Офлайн-метрика 11.67%
   считается на `lk_orders`, дашборд — на XLSX (11.37/14.53). Это не ошибка
   кода, но перед продакшеном нужно свести источники.

3. **Кросс-процессный lock пересчёта.**
   `precomputeMu` защищает только внутри процесса. CLI `recompute` и `serve`
   могут запуститься одновременно. Для продакшена — `pg_advisory_lock`.

4. **Короткий блок после фильтрации.**
   Если из предрасчёта выпали купленные/недоступные товары, блок может быть
   меньше `limit`. Fallback на летучую модель не срабатывает, если остался
   хотя бы один товар.

5. **Планировщик без таймаута.**
   `context.Background()` в фоновом пересчёте. Зависший запрос к БД не
   отменяется. Нужен таймаут и лог прогресса.

6. **`internal/httpapi/admin.go` — монолит.**
   HTML/JS и API в одном файле на тысячи строк. Любая правка рискованна.

7. **OpenAPI не проверяется контрактным тестом.**
   Спека написана вручную; при изменении полей может разойтись с кодом.

### Minor

- На дашборде числа P@3 захардкожены, а не читаются из последнего бэктеста.
- Матчинг внешних источников эвристический, есть ложные совпадения.
- Нет авторизации — сознательно для демо.
- Нет адаптера к ЛК — сознательно, задача отдать API.
- Нет E2E-теста полного сценария «гипотеза → витрина → событие → решение».

## Вердикт

**К демо — готово.** Критических дефектов не осталось; ключевые сценарии
проверены. Для продакшена нужны: изоляция тестовой БД, advisory lock,
таймаут планировщика, контрактные тесты и разбиение `admin.go`.
