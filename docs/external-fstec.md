# Реестр ФСТЭК: сертифицированные средства защиты

## Что мешало

Не VPN. Сайт `reestr.fstec.ru` использует сертификат `Russian Trusted Sub CA`,
которого нет в стандартном хранилище, и отдаёт 403 без браузерного User-Agent.
Поэтому обычный `curl` падал.

Рабочий способ:

```bash
curl -k -A 'Mozilla/5.0 ... Chrome/120' https://reestr.fstec.ru/
```

Для продакшена нужно добавить корневой сертификат Минцифры в trust store, а не
отключать проверку TLS. Для прототипа оставлено `-k` с явной пометкой.

## Что импортировано

Выгрузка «Государственный реестр ССЗИ» (ODS):

| Показатель | Значение |
|---|---:|
| Сертификатов | 1 681 |
| Просрочено | 891 |
| Сопоставлено с каталогом | 100 сертификатов |
| Покрыто товаров | 229 |
| Связей certificate → SKU | 582 |

Поля: номер сертификата, дата внесения, срок действия, наименование средства,
требования, схема, лаборатория, орган, заявитель, адрес, поддержка.

## Как сопоставляли

1. Точное вхождение нормализованного названия продукта в название SKU.
2. Если не нашлось — два редких отличительных слова (document frequency ≤ 10),
   не более 8 товаров на сертификат.

Первый проход дал 327 связей, второй — 255. Без ограничений второй проход давал
32 тысячи связей и явный мусор, поэтому оставлен только строгий вариант.

## Что это даёт

- **Официальное подтверждение** security-продукта: номер сертификата и срок.
- **Риск просрочки**: 891 сертификат просрочен — это сигнал не рекомендовать
  продукт как «сертифицированный».
- **Класс защиты** из требований и названия.
- **Доказательство для связи**: certificate → SKU можно показывать в карточке.

## Ограничения

- В реестре продукт с версией, в каталоге — SKU с редакцией и сроком.
- 100 из 1 681 сертификата сопоставились: нужны алиасы и нормализация версий.
- Сертификат подтверждает продукт, а не совместимость с другим продуктом.

## Воспроизведение

```bash
python3 analysis/import_fstec.py
python3 analysis/link_fstec.py
```

`import_fstec.py` скачивает ODS, конвертирует через LibreOffice и пишет в
`fstec_certificates`. `link_fstec.py` строит связи с `lk_items`.

## Сертификат в витрине

В системной панели витрины у каждой рекомендации видно:

- `fstec: №... · до ...` — действующий сертификат;
- `fstec: №... · просрочен` — срок истёк;
- `fstec: нет` — сопоставленного сертификата нет.

Клиентская карточка показывает бейдж **«Сертифицировано ФСТЭК»** только при
действующем сертификате. Просроченный сертификат бейдж не даёт — продукт не
называется сертифицированным.

Это важно: 891 из 1 681 сертификата уже просрочен. Система не должна
показывать их как действующие.

## Сертификат в каталоге

В «Каталоге»:

- фильтр **«с сертификатом ФСТЭК»** показывает только связи, где хотя бы у
  одной стороны есть действующий сертификат;
- в карточке связи видны строки «Источник: ФСТЭК №…» и «Цель: ФСТЭК №…»;
- просроченные сертификаты помечены красным;
- если сертификата нет — «ФСТЭК — нет».

На демо-данных фильтр даёт 255 связей с действующим сертификатом хотя бы у
одной стороны.

## Влияние на рекомендации

Сертификат используется как сигнал ранжирования:

| Состояние | Влияние |
|---|---|
| Действующий сертификат | `score + 0.06` |
| Только просроченный | `score × 0.95` |
| Нет сертификата | без изменения |
| Режим «только сертифицированные» | товары без действующего сертификата не показываются |

В витрине клиента появился переключатель **«только сертифицированные»**
(в системной панели). В API это поле `certified_only`:

```bash
curl -X POST localhost:8080/v1/recommendations \
  -H 'Content-Type: application/json' \
  -d '{"client_id":"C11191","certified_only":true,"limit":3}'
```

Бейдж «Сертифицировано ФСТЭК» показывается только при действующем сертификате.

Ограничение: буст подобран эвристически, без A/B-замера. Чтобы утверждать
эффект, нужен запросный интент «сертифицированное» или размеченный тест.

## Политика для регулируемых отраслей

Для отраслей:

- медицинские организации;
- образование и наука;
- органы власти;
- финансы (банки, страхование)

по умолчанию включается `certified_only`: в блоке только товары с действующим
сертификатом ФСТЭК.

Политика — настройка, а не жёсткое правило. Её можно выключить:

- в витрине галочкой «только сертифицированные»;
- в API: `"certified_only": false`.

В ответе API есть `certified_only` и `certified_policy`, чтобы было видно,
применена ли отраслевая политика.

Если в названии товара заявлена сертификация, а сертификат просрочен, в витрине
показывается янтарный бейдж **«Сертификат истёк»**, а не зелёный
«Сертифицировано ФСТЭК».
