# Разрезы в живой выдаче

Три сигнала, которые не заменяют друг друга:

| Сигнал | Роль |
|---|---|
| co-purchase / relations | основной ранкер |
| decayed demand | поддерживающий: холодный старт и tie-break |
| renewal | отдельный B2B-срез по сроку лицензии |
| family / category | объяснение, не жёсткий голос |

## Decayed demand

`catalog.PopularityScores` считает спрос с затуханием:

```text
weight = 0.5 ^ (age_weeks / 8)
```

- half-life = 8 недель;
- учитываются все покупки, без искусственного отсечения по дате;
- фильтр по `status = active` и аудитории;
- возвращает `product_id → score`.

В движке:

1. Если после relations не набралось ни одного кандидата — добавляем
   популярные товары как `cross_sell` с evidence `demand`.
2. Если кандидаты есть — даём небольшой буст `+0.05 * demand / max`
   существующим кандидатам.
3. После rules и diversify `FillPopular` добирает до 3 рекомендаций,
   если слотов не хватило.
4. Популярные товары не вытесняют renewal, upsell, alternative и
   co-purchase-связи.

Почему не «заменить популярность везде»: на реальном датасете замена
популярности на `decay_8w` даёт **+1.20 п.п.** B2B A (CI [+0.30; +2.21]),
но в синтетическом eval холодный старт имеет свой ground truth. Поэтому
сначала поддерживающий слой, а не замена.

## Renewal

- окно — 90 дней до конца лицензии;
- просроченные лицензии до 30 дней назад тоже попадают;
- evidence теперь содержит срок:

```text
лицензия действует до 2026-12-09, продление через 14 дней
```

В офлайн-замере:

- 40.4% повторных покупок B2B попадают в 300–430 дней;
- медиана — 364 дня;
- top-3 accuracy по сроку продления — 98.8%.

## Family / category

Это не отдельные голоса в топ-3:

- `upgrade`, `bundle`, `accessory`, `adjacent_task` уже приходят из
  конструктора связей;
- family/category используются в evidence и объяснении;
- жёсткое пересечение разрезов проверено и проигрывает: 5.82% против
  9.44% у baseline.

## Eval

```text
precision@1 = 0.84
precision@3 = 0.92
recall@3    = 0.92
violations  = 0
fallback    = 0
evidence    = 100%
```

Предыдущие 0.86/0.94 включали fallback-кейс как автоматический хит.
Теперь fallback-кейс оценивается по фактическим товарам, поэтому метрика
честнее. Гейт проходит.
