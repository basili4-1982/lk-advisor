### Формат `cross_sell/list`

Запрос:

```json
{"clearCache": true}
```

Ответ:

```json
{
  "status": "shown",
  "data": [
    {
      "link": "https://store.softline.ru/...",
      "image": "https://img.softline.com/...",
      "name": "Название товара",
      "vendorName": "Вендор",
      "vendorLink": "https://store.softline.ru/...",
      "price": 738.99,
      "priceWithDiscount": 738.99
    }
  ]
}
```

Нет `reason`, `evidence`, `score`, `product_id` или графа. `status` управляет показом блока — вероятно, отсюда Fill Rate 54%.

## Что это значит для нас

1. Наш ответ можно встроить в тот же контракт: `status` + `data`, добавив `reason`, `evidence`, `score`, `graph`.
2. Нужен адаптер: `user/info` + `orders/products` → профиль; `cross_sell/list` → наш топ-3.
3. Отрасли в ЛК нет — её надо получить из сета или передать в профиле при открытии.
4. Юрлицо может иметь B2C-товары: персону считаем распределением, а не одним ярлыком.
5. Истёкший Adobe — прямой сценарий замены/аналога; текущий блок его игнорирует.
6. Нужен реальный кейс `lk-36612` в демо: сравнить текущие 6 карточек и наш топ-3 с причинами.

## Ограничения

- Токены и куки не сохраняем.
- Тестовый аккаунт может меняться; данные использовать как пример, не как фиксированный фид.
- Отрасль и B2B/B2C-флаг требуют отдельного подтверждения от организаторов.
