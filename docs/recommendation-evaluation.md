# Замер качества рекомендаций

## Метод

Три временных среза: 01.05.2026, 01.07.2026, 01.09.2026.

Для каждого клиента:

- `owned` — покупки до среза;
- `target` — покупки после среза;
- рекомендации top-3 из активных связей + popular fill;
- baseline: только popular и только co-purchase;
- проверка жёстких правил: уже куплено, нет в наличии, аудитория.

Дополнительно: целевой сценарий «следующий заказ» и варианты с
неподтверждёнными связями и `variant_of`.

## Результаты

Срез 01.07.2026, 1 907 клиентов:

| Режим | P@3 | Hit rate | Клиентов с блоком |
|---|---:|---:|---:|
| Popular | 2.03% | 6.1% | 1907/1907 |
| Co-purchase only | 0.54% | 1.5% | 1030/1907 |
| **Текущая выдача** | **2.03%** | **6.1%** | 1907/1907 |
| + неподтверждённые связи | 2.10% | 6.0% | 1907/1907 |
| + `variant_of` | 2.18% | 6.5% | 1907/1907 |
| Следующий заказ | 1.31% | 3.9% | 1907/1907 |
| Popular, следующий заказ | 1.34% | 4.0% | 1907/1907 |

Срезы 01.05 и 01.09 дают тот же порядок: P@3 1.4–2.2%, текущая выдача
практически совпадает с popular.

## Валидность

Жёсткие правила:

| Проверка | Нарушений |
|---|---:|
| Уже купленный товар в блоке | **0** |
| Товар без наличия | **0** |
| Несовпадение аудитории | **0** |
| Короткий блок у текущей выдачи | **0** |

То есть рекомендации **формально валидны**: не предлагают купленное, снятое с
продажи или чужой аудитории.

## Сертификаты

- доля рекомендаций с действующим сертификатом: 0.8–0.9%;
- доля с просроченным: 0.7%;
- включение/выключение буста не меняет P@3 на этом протоколе: сертифицированные
  товары почти не попадают в топ-3.

## Главный вывод

Сейчас рекомендательная выдача — это **popular с редкими связями**.

- Связи покрывают слишком мало клиентов: co-purchase даёт блок только 1–2%
  клиентов.
- Активных связей мало, поэтому popular fill доминирует.
- Офлайн-модель, которая показывает 11–14% P@3 на дашборде, **не подключена**
  к serving. Это разные алгоритмы и разные протоколы.

## Что делать

1. Перенести офлайн-модель в `catalog.Serve`: кандидаты по всему каталогу,
   а не только по прямым связям от купленного.
2. Использовать реестр классов: для клиента без истории — популярное внутри
   класса, а не общий popular.
3. Включить кандидатные связи и `variant_of` (небольшой, но измеримый прирост).
4. Прогнать тот же протокол, что на дашборде, чтобы сравнивать одинаково.
5. Сертификат оставить как guardrail/буст для интента «сертифицированное»,
   а не как общий сигнал.

## Что подключили

Офлайн-модель теперь работает в выдаче:

1. `analysis/precompute_recommendations.py` считает top-10 для каждого клиента
   и складывает в `client_recommendations`.
2. `catalog.ServeHybrid` сначала читает предрасчёт, фильтрует купленное,
   недоступное и сертификаты; если предрасчёта нет — считает гибрид на лету.
3. Сертификат как общий буст убран: замер показал −0.1 п.п. к P@3.
   Сертификат остаётся фильтром (`certified_only`) и бейджем.

Почему live-замер по историческим целям даёт 0%: сегодняшняя выдача исключает
всё, что клиент уже купил, включая тестовые покупки. Это правильное поведение,
но воспроизвести prospective-метрику можно только на дате среза, а не на
текущей базе. Честная оценка качества — 11.67% из офлайн-протокола; живой
эффект надо мерить A/B на новых клиентах.

## Сертификат как сигнал: замеры

Буст сертификата на официальном протоколе:

| Множитель | P@3 all | P@3 security targets |
|---|---:|---:|
| 1.00 (без буста) | **11.77%** | **13.72%** |
| 1.05 | 11.77% | 13.72% |
| 1.10 | 11.67% | 13.54% |
| 1.20 | 11.57% | 13.37% |

Вывод: глобальный буст не улучшает P@3 и при усилении вредит. Сертификат
корреллирует с качеством, но не предсказывает следующий товар.

Поэтому сертификат используется иначе:

- жёсткий фильтр `certified_only`;
- бейдж и срок в витрине;
- тай-брейкер: при разнице score < 0.02 сертифицированный товар выше;
- фильтр каталога «с сертификатом ФСТЭК».

Для интента «сертифицированное ПО» это сильный сигнал, но его нужно включать
явно, а не размазывать по общему ранжированию.

## Отраслевая политика

Для регулируемых отраслей по умолчанию включён `certified_only`. Это
сознательное решение для демо: в медицине, образовании, госсекторе и финансах
сертификат важнее общего ранжирования.

На этапе внедрения политику можно отключить:

- галочкой в витрине;
- параметром `certified_only=false`;
- списком `RegulatedIndustries` в коде.

Глобальный буст сертификата не используется: он не улучшает P@3. Сертификат
работает как фильтр, тай-брейкер и compliance-бейдж.
