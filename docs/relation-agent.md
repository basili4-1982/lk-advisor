# Агент разметки связей

Агент предлагает связь между двумя товарами, используя активные шаблоны из `/admin#types`. Он не пишет в каталог: сначала показывает тип, уверенность, причину и evidence, затем админ подтверждает.

## Поток

1. Админ выбирает «откуда» и «куда» в блоке «Агент разметки».
2. Сервис собирает промпт из:
   - карточек двух товаров: название, категория, подкатегория, вендор, аудитория;
   - активных шаблонов связей: код, описание, примеры, направление, поведение.
3. LLM возвращает строгий JSON:

```json
{
  "type": "adjacent_task",
  "confidence": 0.86,
  "reason": "Оба продукта закрывают соседние задачи.",
  "evidence": ["категории различаются, но задачи рядом"]
}
```

4. Валидатор проверяет:
   - тип есть среди активных шаблонов;
   - `confidence` в диапазоне 0–1;
   - нет выдуманных кодов.
5. Результат показывается с кнопками:
   - «Добавить как предложение» — `llm_suggested` или `quarantine`;
   - «Добавить и подтвердить» — `confirmed`.

## Статусы

| Уверенность | Что делает агент |
|---|---|
| `>= 0.7` | предлагает `llm_suggested`, движок может показать |
| `< 0.7` | ставит `quarantine`, движок не показывает |
| `none` | связь не предлагается |

## Без LLM

Работает эвристика:

- одинаковая подкатегория → `same_task`, `quarantine`;
- одна категория, разные подкатегории → `adjacent_task`, `quarantine`;
- разные категории → `none`.

Это не замена LLM, а честный резерв для демо без ключа.

## API

```bash
curl -s -X POST localhost:8080/v1/admin/relations/agent/propose \
  -H 'Content-Type: application/json' \
  -d '{"from_id":"prod-pdf","to_id":"prod-backup"}'
```

## Когда придут данные партнёра

Пара-ручка уже готова. Следующий шаг — batch:

- взять пары без связи из категории или CSV;
- прогнать через того же агента;
- сохранить предложения в очередь на проверку;
- подтверждённые писать в `product_relations`.

Промпт менять не нужно: описания и примеры уже приходят из `relation_types`.
