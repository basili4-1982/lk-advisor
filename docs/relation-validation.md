# Ручная валидация связей

Очередь нужна, чтобы LLM и агент не писали в каталог без проверки. В `/admin` есть вкладка **«Валидация»**.

## Что попадает в очередь

- `quarantine` — низкая уверенность или эвристика без LLM;
- `llm_suggested` — уверенное предложение ИИ, но ещё не подтверждённое человеком.

Связи `confirmed` и `rejected` в очередь не попадают.

## Что видно по каждой связи

- откуда → куда;
- тип и его человеческое название;
- уверенность;
- источник: `llm`, `agent`, `admin`, `dataset`;
- причина предложения;
- evidence: факты из карточек или шаблона;
- статус.

## Действия

- **Подтвердить** — статус `confirmed`, движок начинает использовать связь.
- **Отклонить** — статус `rejected`, движок не использует.
- **Отложить** — оставить как есть, просто не выбирать.
- **Заметка** — сохраняется в `review_note`, видна в аудите.

Можно работать по одной связи или пачкой: выбрать чекбоксами и нажать «Подтвердить выбранные» / «Отклонить».

## Что пишется в БД

```text
product_relations.reason
product_relations.evidence
product_relations.reviewed_by
product_relations.reviewed_at
product_relations.review_note
```

Плюс запись в `admin_audit` с действием `relation.review`.

## API

```bash
# очередь
curl -s 'localhost:8080/v1/admin/relations/review?status=quarantine,llm_suggested&limit=100'

# решение по одной или нескольким
curl -s -X POST localhost:8080/v1/admin/relations/review \
  -H 'Content-Type: application/json' \
  -d '{
    "decision":"confirm",
    "note":"проверено по карточкам",
    "items":[{"from_id":"prod-sl-86","to_id":"prod-backup","type":"adjacent_task"}]
  }'
```

## Как это связано с агентом

Агент разметки возвращает предложение. Кнопка «Добавить как предложение» пишет связь со статусом `llm_suggested` или `quarantine`, причиной и evidence. Дальше она появляется в очереди валидации. Кнопка «Добавить и подтвердить» сразу ставит `confirmed`.

## Ограничения демо

- Нет ролей: любой, кто открыл админку, может подтверждать.
- Нет SLA и назначения reviewer; для пилота добавим `reviewer_id` и очередь по владельцу.
- Для 200k товаров очередь нужно paginate и фильтровать по категории/источнику; API уже принимает `status` и `limit`.
