# LK Advisor — безопасность стенда

## Что закрыто

- **Админка и админ-API.** `/admin`, `/v1/admin/*` и `/v1/ask` закрыты Basic Auth
  на уровне Caddy. Без логина — `401`.
- **Промпт разметки.** Не отдаётся наружу: экран «Промпт для разметки связей»
  и эндпоинт `/v1/admin/relation-types/prompt` удалены. Промпт собирается
  на сервере из активных шаблонов; менять шаблоны может только админ.
- **LLM-ключ.** Хранится в переменных окружения контейнера, в репозиторий
  не попадает.
- **Сырой датасет.** Не публикуется и не коммитится.

## Контейнеры

- приложение `lk-app`: non-root пользователь, read-only rootfs, `tmpfs /tmp`,
  `no-new-privileges`, порт 8080 не опубликован на хост;
- база `lk-db`: доступна только внутри Docker-сети, наружу порт не отдаётся;
- публичный вход — только Caddy: TLS Let's Encrypt, HSTS, `nosniff`,
  `X-Frame-Options`, `Referrer-Policy`.

## Границы агента

LLM-агент не имеет инструментов shell, файловой системы или произвольного
HTTP. Его инструменты — чтение профиля клиента, лицензий, заказов, каталога,
связей и правил. Поэтому prompt injection может исказить текст ответа, но не
даёт выполнить команду на сервере или прочитать переменные окружения.

## Что добавить перед продакшеном

- SSO и роли вместо общего Basic Auth;
- rate limit и WAF на публичные ручки;
- аудит действий администраторов и ротация ключей;
- отдельные сети для приложения, БД и мониторинга;
- секрет-менеджер вместо env-файла.
