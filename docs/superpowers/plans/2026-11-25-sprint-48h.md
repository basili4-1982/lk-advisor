# LK Advisor — план спринта 48 часов

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** рабочий бэкенд рекомендаций и агентского чата на PostgreSQL, с тестами, eval и демо, к 28.11.2026 10:00 МСК.

**Architecture:** Go-сервис, PostgreSQL, профиль в материализованном представлении по шардам, детерминированный движок рекомендаций. LLM только размечает карточки офлайн и формулирует ответ по готовому отчёту; числа возвращают инструменты.

**Tech Stack:** Go 1.26, `net/http`, `database/sql` + `pgx`, PostgreSQL 16, Docker, GitHub Actions.

**Spec:** `README.md`, `brief.md`, `api-contract.md`, `algorithm.md`, `data-model.md`, `agent-layer.md`, `chat-rules.md`.

## Global Constraints

- Только PostgreSQL. SQLite не используем ни в демо, ни в тестах.
- `client_id` всегда из сессии или пути запроса, никогда из текста вопроса.
- Числа в ответе — только из БД или инструментов; LLM не добавляет числа.
- Правила применяются до скоринга и до LLM. Акция не поднимает запрещённый товар.
- В ответе нет PII: только `client_id`, товары, причины, evidence.
- Seed 42. Один вход — один и тот же JSON.
- Не больше трёх рекомендаций, не больше 6 шагов агента.
- Все суммы в рублях без НДС.

## Review Focus

1. Свежая покупка ещё не в профиле: клиент купил, MV не обновился, рекомендация устарела. Тест: enqueue → refresh → Get видит покупку.
2. Акция на запрещённый товар не должна поднимать его. Тест: promo + `excludes` → товара нет.
3. LLM добавила число, которого нет в evidence. Тест: ответ заменяется шаблоном.
4. Вопрос вне области не должен вернуть данные другого клиента. Тест: чужой `product_id` и `client_id` в вопросе игнорируются.
5. Шард при записи и чтении считается одинаково. Тест: `Shard(id, N)` детерминирован, refresh одного шарда не трогает соседний.
