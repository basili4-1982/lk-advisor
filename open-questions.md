# Вопросы заказчику и допущения

## 0. Ответы заказчика 23.11.2026

Что подтверждено по нашей задаче:

- демо — тестовый клиент получает персональные предложения: дополнительные товары (cross-sell), расширенную версию продукта (upsell) и продление лицензии (renewal);
- подбор учитывает историю покупок, активные лицензии и поведение клиента;
- отдельного требования определять цель текущего визита, проверять заказ или скачивать документ — нет; событие визита остаётся опциональным сигналом;
- у каждого предложения должно быть объяснение, почему оно подходит клиенту.

Что не ответили:

- готовые связи между товарами не обещаны. **Решение: строим связи сами** — LLM извлекает их из карточек товаров, валидатор подтверждает. Это наше преимущество, а не обход ограничения: качество связей определяет качество рекомендаций, и мы его контролируем;
- состав данных и каталог — только 26.11, не раньше.

## 1. Открытые вопросы

1. Какие данные по клиенту можно читать: покупки, лицензии и сроки, заказы, скачанные документы, обращения? Есть ли API или выгрузка?
2. Можно ли получить обезличенную выборку: 50–100 клиентов, история покупок, лицензии, заказы? В каком формате?
3. Что должно быть в ответе: `product_id`, ранг, score, тип (cross-sell / upsell / renewal), причина, срок действия? Нужен ли batch-режим?
4. Какие ограничения по latency и режиму: real-time на каждый вход или расчёт раз в сутки?
5. Что возвращать, если рекомендаций нет: пустой список, популярные товары сегмента или ничего?
6. Какие связи и апгрейды запрещены: несовместимые лицензии, апгрейд только через менеджера, конкурентные бренды, экспортный контроль? Нужен список запретов.
7. Есть ли лог показов, кликов и покупок рекомендаций? Если нет — как оценивать: precision@K на размеченной выборке или A/B?
8. Какие метрики считаем успехом: CTR, принятие, повторная покупка, средний чек? За какой период?
9. Кто может выступить экспертом-валидатором связей и сколько времени выделить на хакатоне?

Закрыто ответом 23.11: цель визита определять не требуется; типы предложений — cross-sell, upsell, renewal; сигналы — история, лицензии, поведение.

## 2. Допущения, если ответов нет

| Тема | Допущение |
|---|---|
| Каталог | лицензии, подписки, услуги, сопутствующее железо для юрлиц |
| Клиент | SMB, IT-менеджер или закупщик, 1–10 покупок |
| Данные | покупки, лицензии со сроками, заказы, документы, события входа |
| Связи | готовых нет: извлекаем сами из карточек, валидатор подтверждает |
| Правила | несовместимость, экспортный контроль, менеджер, уже куплено |
| Ground truth | 50 кейсов, в каждом есть acceptable alternatives |
| Метрики | precision@1 и @3, ноль нарушений, fallback rate |
| Режим | real-time, p95 до 100 мс без LLM |
| Оценка | демо на 6 сценариях + offline-метрики |
